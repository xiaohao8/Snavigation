## 解决 favicon 加载慢：预下载到本地

用户反馈图标加载偏慢。根因：原 `js/icons.js` 的 `faviconUrl` 用 dnspod `proxy_favicon` 端点 + favicon.im 回退，但 **dnspod 该端点返回的是 JSON 包装的 HTML 错误页（非图片）**，导致每个图标都要先失败再回退到 favicon.im，慢且不稳。
- **新方案**：把 78 个去重域名的 favicon **预下载到本地 `img/favicons/`**，运行期优先用本地文件（同域瞬时 + 浏览器缓存），本地缺失才回退 favicon.im。
- **可达源探测（沙箱）**：dnspod(返回JSON不可用) / duckduckgo(000被墙) / google s2(000被墙) / clearbit(000被墙) / favicon.im(`-L` 跟随 302 可用，但 github 类站点返回 **SVG**，部分返回 webp/ico/png)。最终用 **favicon.im + curl -L** 下载。
- **格式处理**：favicon.im 返回混合格式（png/svg/ico/webp），按 `content_type` 存为对应扩展名；`<img>` 三种格式均可渲染。
- **精确命中（避免 404 试探）**：在 `icons.js` 内嵌 `FAV_MAP = {domain: ext}`（77 条，覆盖 78 域名中的 77，仅 `www.mianfeixiaoshuo.com` 始终取不到→走字母底兜底）。`faviconUrl(domain)` 返回 `img/favicons/{domain}.{ext}`；`onerror` 简化为「本地缺失→favicon.im→隐藏(露字母底)」。
- **校验**：jsdom 端到端测试 78 域名 → 77 精确命中本地文件 + 1 兜底 = PASS；本地服务器对 svg/webp/ico/png 均 200 且 MIME 正确；`node --check` 通过；`img/favicons/` 共 77 文件 / 918K。辅助 `_domains.txt` 已删。
- **注意**：dnspod 端点已确认不可用，不要再把它当图标源；favicon.im 是本项目可用的主要外部源。
