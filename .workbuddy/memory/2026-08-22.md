# 2026-08-22

## 优化「设置页 ↔ 快捷方式页」选项同步

- 问题：`.mark`（Dock 打开的快捷方式页）原本是 **硬编码静态 HTML**（8 分类 tab），与设置页「快捷方式」tab 管理的 `quick_list` cookie 完全脱节，无法同步/管理。
- 方案：让 `.mark` 改为由 `quick_list` 动态渲染，与首页 `.quick-all`、设置页「快捷方式」tab 共用 **同一数据源**，实现统一管理与状态同步。
- 关键改动（js/set.js）：
  - 新增 `QUICK_CATS = ['常用','AI','工具','办公','开发','娱乐','学习','设计']` 与 `renderMarkShortcuts()`：读取 `getQuickList()`，按 `cat` 归集到各分类 `.mainCont` 的 `.quick-alls`（只替换内部 HTML，保留 `.mark` 容器与 tab 切换）。
  - `openBox()`、文档 ready、以及快捷方式 新增/覆盖/编辑/删除/重置 各分支均调用 `renderMarkShortcuts()`。
  - `quick_list_preinstall` 33 条默认项增加 `cat` 字段（按 8 分类分布；AI/设计 默认空，显示 `.mark-empty` 提示）。
  - 设置表单 `quick_add_content` 增加「分类」下拉框；`quick_add_save` 读写 `cat`，`edit_quick` 回填；`[data-mark-add]` 从对应分类「添加」入口进入设置时预选该分类。
  - 书签增改删后调用 `BookmarkPanel.refresh()`。
- CSS：新增 `.add_content select`（对齐输入框）与 `.mark-empty` 样式。
- 验证：用最小 DOM 桩在 node 沙箱中真实执行 `renderMarkShortcuts`，确认 33 条按分类正确归集、空分类显示提示、无异常（PASS）。
- 注意：`.mark` tab 顺序与 `QUICK_CATS` 必须一致，否则分类错位。

## 修复：默认项未归集 + 分类下拉 UI 异常

- 问题 1（分组错误）：用户浏览器已存有**旧版 `quick_list` cookie（无 `cat` 字段）**，被 `getQuickList` 原样返回 → 全部落入「常用」，其余 7 个分类为空（即"默认项未按分类归集"）。
- 修复 1：`getQuickList` 增加 `backfillQuickCat()` —— 按 key 从 `quick_list_preinstall` 回填 `cat`（自定义项/未知分类归「常用」），dirty 时写回 cookie。升级后默认项正确归集。
- 问题 2（下拉 UI 异常）：`<select>` 用原生外观（边框/箭头）与本应用无边框输入框风格冲突，且暗色下 `<option>` 弹层不可读；此外 `.favicon-row`/`.favicon-pick` **完全没有 CSS**，图标行撑破表单布局。
- 修复 2：`.add_content select` 改 `appearance:none` + 自定义浅灰箭头(data-URI SVG) + 显式 `color:#fff` + 暗色 `option` 列表；`body[data-theme="glass"]` 下箭头/文字改深色；新增 `.favicon-row`(flex 横向) / `.favicon-pick`(胶囊按钮) 样式。
- 验证：node 沙箱真实执行 `getQuickList`+`renderMarkShortcuts`，模拟旧 cookie 自动回填 cat、归集正确、空分类提示、自定义项归常用（ALL PASS）；`node --check`、`style.css` 大括号平衡均 OK。

## 修复：原有书签数据丢失（严重回归）

- 问题：上轮把快捷方式页数据源整体换成设置页 `quick_list`（醉里博客/cloudflare 等 33 条），**丢弃了原始 `.mark` 页那套精选书签**（Kimi/千问/豆包/ChatGPT/QQ邮箱/Stack Overflow/Wallhaven/Figma…），用户反馈"原有数据没了"。
- 修复：以**原始 `.mark` 书签为统一数据源的默认内容**合并回来。
  - 新增 `mark_bookmarks` 数组（原始 8 分类精选书签，约 77 条，跨分类重复站点仅保留首个分类）。
  - 加载时用 IIFE 重建 `quick_list_preinstall`：**`mark_bookmarks` 优先（决定分类）→ 再补充设置种子中不重复的 URL**。这样默认即含原始数据，且"恢复预设"可还原。
  - `getQuickList` 升级：旧 cookie 一次性 `mergeMarkDefaults()` 补回原始书签（按 URL 去重、不覆盖用户已有项），并用 `quick_migrated_v2` cookie 标记保证只跑一次；随后 `backfillQuickCat()` 按 URL 从预装回填分类（自定义项归常用）。
  - `backfillQuickCat` 改为**基于 URL 的映射**（不再按 key），与新生成 key 解耦，更鲁棒。
- 验证：node 沙箱真实执行，场景 A 全新加载默认 101 条且全部有合法 cat、原始书签+设置种子均在；场景 B 旧 cookie 升级后补回 Kimi/Wallhaven/腾讯元宝、cat 回填、迁移标记写入；场景 C 迁移仅一次（项不增长）。ALL PASS。
- 注意：单一数据源模型下每项仅一个分类，跨分类站点（如 哔哩哔哩/抖音/知乎/网易云音乐）归入首个分类（常用），不会丢失，仅不再跨分类重复展示。
